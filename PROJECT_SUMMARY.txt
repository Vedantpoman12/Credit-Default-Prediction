CREDIT DEFAULT PREDICTION WITH FAIRNESS CONSTRAINTS - PROJECT SUMMARY
======================================================================
Educational artefact, NOT for real lending decisions. (BTECH CAP 501)

Built by following "Credit_Default_Fast_Track_Plan_and_Prompts.docx", Steps 1 to 8.
Sections 4 and 8 are the build history. The CURRENT state (deployed policy,
test result, latency, CI) is in sections 5 and 9.
Everything from the previous version was deleted except the raw datasets, which
were moved to data/raw/.


1. WHAT THE PROJECT DOES
------------------------
It predicts whether a credit-card client will default next month, then makes an
approve / refer / decline recommendation that is constrained to be fair across
age bands. The fairness criterion is equal opportunity: defaulters are caught at
the same rate (TPR) in every age band. The model comes with explanations
(SHAP, DiCE), a REST API, drift monitoring, CI gates and EU AI Act style
documentation.


2. DATASETS (adapted from the plan)
-----------------------------------
The plan names "Give Me Some Credit" and German Credit, but the repository holds
different data, so:
  - Primary dataset: data/raw/default_of_credit_card_clients.csv (UCI Taiwan,
    30,000 rows, 22.1% default). AGE gives the protected age bands
    (<25, 25-34, 35-44, 45-54, 55-64, 65+). AGE and SEX are never model features.
  - Fairness sandbox (stands in for German Credit, which has explicit sex and age):
    data/raw/application_record.csv + credit_record.csv (Kaggle credit card
    approval; label = ever 60+ days past due, 1.69% default).
  - Dataset-specific adaptations:
      sentinels 96/98 -> undocumented codes EDUCATION 0/5/6 and MARRIAGE 0
      "income" drift  -> LIMIT_BAL and PAY_AMT1-6 used as the income proxy
      base rate 6.7% -> 12%  becomes  22.1% -> 40% (same ~1.8x rise)


3. TOOLS AND LIBRARIES
----------------------
Python 3.14 (venv/), pandas 2.3, scikit-learn 1.9, XGBoost 3.4, Optuna 5.0,
Fairlearn 0.15, SHAP 0.54, dice-ml 0.12, Evidently 0.7, MLflow 3.17 (sqlite:
mlflow.db), FastAPI + Uvicorn, pytest, Docker, GitHub Actions.
Exact pins are in requirements.txt. macOS also needs `brew install libomp`
for XGBoost.

6. NOTES AND DEVIATIONS
-----------------------
  - The datasets differ from the plan (see section 2).
  - Python 3.14 and a python:3.14-slim Docker image are used, because only 3.14
    is installed and the pinned packages need >= 3.11.
  - The Docker image was not built locally (the Docker daemon was not running);
    CI now builds it and smoke-tests /health and /score (section 9).
  - The 65+ band (about 16 people per split) is reported but excluded from gap
    metrics (n < 30 rule).
  - To rerun the test evaluation, the lock file has to be moved aside manually
    (this is intentional; done once for the deployed model, decision #24).

8. RETRAINING (2026-10-27)
--------------------------
  What changed
    src/features/pipeline.py   FeatureBuilder (first pipeline step, stateless):
                               UTIL_1-6, PAY_RATIO_1-5, UTIL_MEAN/MAX/TREND,
                               MONTHS_LATE, MAX_DELAY, MEAN_STATUS,
                               PAID_TO_BILLED, HEADROOM (21 -> 40 features)
    config/config.yaml         Optuna 100 trials x 5-fold; utilisation
                               features winsorised
    src/models/train_xgb.py    early stopping 100 rounds, up to 2,000 trees
    src/models/calibrate.py    never selects a calibrator that outputs 0 or 1
                               -> Platt scaling
    src/fairness/policy.py     GroupThresholds: deterministic equal-opportunity
                               thresholds per age band (deployed briefly; replaced
                               by ExponentiatedGradient, decision #21)
    src/explain/shap_explain.py  SHAP reports engineered features by name
    src/explain/recourse_dice.py returns "no actionable change" instead of
                               crashing when DiCE finds nothing
  Effect (raw model scores, same validation rows)
    before: CV AUC 0.7850, val AUC 0.7801, PR-AUC 0.5532
    after:  CV AUC 0.7904, val AUC 0.7828, PR-AUC 0.5598
  Why the fairness policy changed
    ThresholdOptimizer's validation gap was entirely random-draw noise
    (expected gap 0.000) and 9-29% of defaulters got coin-flip decisions.
    Deterministic per-band thresholds remove that. The validation gap is
    in-sample; the 55-64 band has too few defaulters (48) to verify a 0.05
    gap on held-out data.
  Not done
    The test set was not re-evaluated (lock file kept).
